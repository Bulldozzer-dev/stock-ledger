Why a repeated request does not change stock twice

A write transaction locks before checking the balance. Stock and history commit together. Each movement has a unique request ID: an identical retry returns the original movement, while a conflicting retry is rejected. Negative stock is rejected. Reconciliation compares balances against recorded changes.

This application runs on your own computer, bound to 127.0.0.1. It has no accounts or deployment hardening. History can be altered by someone with database access. Whole units only; no payments or inventory valuation. See the README for backup, restore and API documentation.
